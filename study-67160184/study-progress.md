## ขั้น 1: ฐานข้อมูล (`schema.sql` + `seed.sql`)

### ไฟล์ไหนทำอะไร
- `schema.sql` = **แบบแปลน**: สร้างตารางและกฎ (ยังไม่มีข้อมูลสินค้า)
- `seed.sql` = **ข้อมูลตั้งต้น**: ใส่หมวดหมู่ 3, ผู้จัดจำหน่าย 3, admin 1, สินค้า 3

เปรียบกับ Excel: ฐานข้อมูล = ไฟล์ · ตาราง = sheet · คอลัมน์ = หัวคอลัมน์ · แถว = ข้อมูล 1 รายการ

### 4 ตาราง

```
categories (หมวดหมู่)     suppliers (ผู้จัดจำหน่าย)     users (ผู้ดูแลระบบ)
 id, name, description     id, supplier_code, name,      id, email,
                            email, phone                  password_hash, role
       ▲                          ▲
       │ category_id              │ supplier_id
       └──────── products (สินค้า) ────────┘
                 id, name, price, sku, stock_quantity
```

`products` ไม่เก็บชื่อหมวดหมู่/ผู้จัดจำหน่ายตรงๆ เก็บแค่เลข id ที่ชี้ไป → backend จึงต้อง `JOIN` เพื่อเอาชื่อมาแสดง

### ศัพท์ที่โผล่ซ้ำ

| ศัพท์ | ความหมาย |
|---|---|
| `PRIMARY KEY` | เลขประจำตัวแถว ไม่ซ้ำ ไม่ว่าง |
| `AUTO_INCREMENT` | ฐานข้อมูลนับเลขเพิ่มให้เอง |
| `NOT NULL` | ห้ามว่าง |
| `UNIQUE` | ห้ามซ้ำทั้งตาราง |
| `DEFAULT` | ค่าเริ่มต้นถ้าไม่ระบุ |
| `CHECK (price >= 0)` | ราคา/สต็อกห้ามติดลบ |
| `DECIMAL(10,2)` | ทศนิยม 2 ตำแหน่ง เหมาะกับเงิน |
| `FOREIGN KEY` | เลขในช่องนี้ต้องมีอยู่จริงในตารางอื่น |

### กฎสำคัญ (อาจารย์ชอบถาม)

| กฎ | ที่ | ผล |
|---|---|---|
| `UNIQUE` | categories.name, suppliers.supplier_code, suppliers.email, products.sku, users.email | เพิ่มซ้ำไม่ได้ → backend ตอบ 500 |
| `name` ซ้ำได้ | suppliers.name, products.name | มีตัวระบุอื่นที่ห้ามซ้ำอยู่แล้ว (รหัส/อีเมล/SKU) |
| `ON DELETE CASCADE` | products.category_id | ลบหมวดหมู่ → สินค้าในหมวดถูกลบตาม |
| `ON DELETE SET NULL` | products.supplier_id | ลบผู้จัดจำหน่าย → สินค้าอยู่ต่อ ช่องผู้จัดจำหน่ายว่าง |
| `supplier_id` ว่างได้ แต่ `category_id` ห้ามว่าง | products | สินค้าต้องมีหมวดหมู่เสมอ แต่ผู้จัดจำหน่ายอาจถูกลบไป |

### ทำไม suppliers มีรหัส และ name ซ้ำได้
- **รหัส (`supplier_code`)**: โจทย์ Phase 1 กำหนด (requirement.md บรรทัด 22) · คนอ่านและอ้างอิงในเอกสารได้ ต่างจาก `id` ที่ไว้ให้ระบบเชื่อมตาราง · ห้ามซ้ำเพราะใช้ระบุตัว · เว้นว่างตอนเพิ่ม ระบบสร้างให้ (`SUP-` + 8 หลักท้ายของเวลา)
- **name ซ้ำได้**: ตัวระบุจริงคือรหัสกับอีเมลซึ่ง UNIQUE อยู่แล้ว และคนละบริษัทอาจชื่อเหมือนกัน · ข้อจำกัดคือเผลอเพิ่มบริษัทซ้ำได้ถ้ารหัส/อีเมลต่าง (trade-off ที่เลือก)
- หลักคิดทั้งระบบ: **ถ้ามีตัวระบุที่ห้ามซ้ำอยู่แล้ว ชื่อปล่อยให้ซ้ำได้** (categories เป็นตารางเดียวที่ name UNIQUE เพราะไม่มีรหัสอื่น)

### `seed.sql` สำคัญตรงไหน
- สินค้าผูกกับหมวดหมู่/ผู้จัดจำหน่ายด้วยเลข เช่น `(1, 1, 'Wireless Ergonomic Mouse', 890.00, 'SKU-ELE-001', 50)` = หมวด id 1, ผู้จัด id 1
- บัญชี admin เก็บ `password_hash` (bcrypt) ไม่ใช่รหัสจริง รหัสเริ่มต้นอยู่ในคอมเมนต์บรรทัด 15 ของ seed.sql
- `ON DUPLICATE KEY UPDATE` (บรรทัด 20): รันซ้ำแล้วรหัส admin กลับเป็นค่าเริ่มต้น ไม่ error
- `schema.sql` ไม่ `DROP` ตาราง `users` (ใช้ `IF NOT EXISTS`) เพื่อไม่ให้ล้างข้อมูลสินค้าแล้วบัญชี admin หาย

### ความหมายของการออกแบบ
หมวดหมู่ 1 อัน มีสินค้าได้หลายชิ้น แต่สินค้า 1 ชิ้นอยู่ได้แค่ 1 หมวด (หนึ่งต่อหลาย) ผู้จัดจำหน่ายก็เช่นกัน · รูปวาดอยู่ที่ `erd.png` / `erd.md`

## ขั้น 2: `src/middlewares/auth.js` (ด่านตรวจ JWT) 59 บรรทัด

### มีหน้าที่ 3 อย่าง + ตัวรวม

| ฟังก์ชัน | บรรทัด | ทำอะไร |
|---|---|---|
| `generateToken(user)` | 13-17 | ออก JWT ให้หลังล็อกอิน ข้างในมี `id, email, role` เซ็นด้วย `JWT_SECRET` อายุ 1 ชม. (ปรับได้ด้วย `JWT_EXPIRES_IN`) |
| `authenticateToken` | 25-39 | ตรวจว่า**มี token และถูกต้อง**ไหม |
| `authorizeRole("admin")` | 42-52 | ตรวจว่า**เป็นบทบาทที่อนุญาต**ไหม |
| `requireAdmin` | 56 | `[authenticateToken, authorizeRole("admin")]` รวม 2 ด่านเรียงกัน |

### ด่านที่ 1 `authenticateToken` ทีละบรรทัด
1. อ่านหัวข้อ `Authorization` ที่หน้าเว็บแนบมา รูปแบบ `Bearer <token>` แล้วตัดเอาส่วน token (บรรทัด 26-28)
2. ไม่มี token → ตอบ **401 `NO_TOKEN`** (บรรทัด 29-31)
3. `jwt.verify(token, secret)` ตรวจลายเซ็นและวันหมดอายุ ผ่าน → เก็บข้อมูลผู้ใช้ที่ `req.user` แล้ว `next()` ไปด่านถัดไป (บรรทัด 32-35)
4. ไม่ผ่าน (ปลอม/แก้ไข/หมดอายุ) → ตอบ **401 `INVALID_TOKEN`** (บรรทัด 36-38)

### ด่านที่ 2 `authorizeRole`
- ไม่มี `req.user` → 401 · `role` ไม่อยู่ในรายการที่อนุญาต → **403 `FORBIDDEN`** · ผ่าน → `next()` เข้า route
- 401 = "ไม่รู้ว่าคุณเป็นใคร" · 403 = "รู้ว่าเป็นใคร แต่ไม่มีสิทธิ์"

### JWT หน้าตาเป็นอย่างไร
`header.payload.signature` สามก้อนคั่นด้วยจุด · payload อ่านได้ (ไม่ได้เข้ารหัส) จึง**ห้ามใส่รหัสผ่าน** · signature คำนวณจาก payload + `JWT_SECRET` ถ้าใครแก้ payload ลายเซ็นจะไม่ตรง → `INVALID_TOKEN`

### ใช้ที่ไหนใน `src/index.js`
ทุก route ที่แก้ข้อมูลเขียนแบบ `app.post("/api/v1/products", requireAdmin, handler)` · ส่วน GET ไม่ใส่ จึงเปิดสาธารณะ · `/auth/me` และ `/auth/change-password` ใช้ `authenticateToken` อย่างเดียว

### เชื่อมกับหน้าเว็บ
`apiFetch` ใน app.js อ่านรหัส error: เป็น `NO_TOKEN` หรือ `INVALID_TOKEN` → ออกจากระบบอัตโนมัติ · 401 จากเหตุผลอื่น (เช่น รหัสผ่านเดิมผิด) ไม่ออกจากระบบ

### ค่าสำรอง secret (บรรทัด 5-10)
ถ้าไม่มี `JWT_SECRET` ใน `.env` ใช้ค่าสำรอง เพื่อให้รันบนเครื่องที่ยังไม่มี `.env` ได้ · เครื่องจริงต้องตั้งเอง (อยู่ใน `.env` ไม่อยู่ในซิป)

### 🎯 อาจารย์ชอบถามเรื่อง endpoint — ใครเรียกแต่ละ endpoint ได้บ้าง (18 ตัว)

| สิทธิ์ | จำนวน | endpoint |
|---|---|---|
| เปิดสาธารณะ (ไม่ต้อง token) | 7 | `GET /health` · `POST /auth/login` · `GET /products` · `GET /products/:id` · `GET /products/:id/price` · `GET /categories` · `GET /suppliers` |
| ต้องมี token (ใครล็อกอินก็ได้) `authenticateToken` | 2 | `GET /auth/me` · `PATCH /auth/change-password` |
| ต้องเป็น admin `requireAdmin` | 9 | `POST` `PATCH` `DELETE` ของ `/products` `/categories` `/suppliers` (อย่างละ 3) |

จำง่ายๆ: **อ่านเปิดหมด เขียนต้อง admin** (ยกเว้น login ที่ต้องเปิด และ 2 ตัวของบัญชีตัวเอง) · รวม 7 + 2 + 9 = 18 ตรงกับ Swagger

### คำถามเช็กความเข้าใจขั้น 2
1. ยิง `DELETE /api/v1/products/1` **โดยไม่มี token** ได้สถานะอะไร และ `code` อะไร
2. token ที่**หมดอายุแล้ว** ได้สถานะอะไร และหน้าเว็บทำอย่างไรต่อ
3. มี token ถูกต้องแต่ `role` ไม่ใช่ admin ได้สถานะอะไร (ระบบนี้มีบทบาทเดียวคือ admin จะเกิดจริงได้ไหม)

## ขั้น 3: `src/services/external-api.js` (API ภายนอก) 66 บรรทัด 🎯 อาจารย์จะถาม

**ทำอะไร:** ไปขออัตราแลกเปลี่ยนจาก `open.er-api.com` (THB → สกุลอื่น) ให้ route `GET /api/v1/products/:id/price` (index.js บรรทัด 190-245) โดยไม่ให้ระบบเราพังตามถ้า API นั้นมีปัญหา

| ส่วน | บรรทัด | ทำอะไร |
|---|---|---|
| `config` | 4-9 | ค่าตั้งต้นอ่านจาก `.env`: timeout 3 วินาที, retry 2 ครั้ง (รวม 3 ครั้ง), backoff ฐาน 500 ms |
| `isRetryable` | 14-18 | ลองใหม่เฉพาะ: ต่อไม่ติด/timeout, **429**, **5xx** — ไม่ลองใหม่ 4xx อื่น (เราส่งผิดเอง ลองกี่ครั้งก็ผิด) |
| `fetchWithRetry` | 21-41 | วนยิงสูงสุด 3 ครั้ง ระหว่างครั้งรอ **backoff**: ฐานเพิ่ม 2 เท่า (500, 1000 ms) แล้วสุ่มครึ่งหนึ่งถึงเต็มฐาน (**jitter**) กันหลายคนยิงพร้อมกัน |
| `getExchangeRate` | 46-64 | ครอบด้วย try/catch คืน `{rate, source}`: `live` สำเร็จ · `unsupported` API ไม่มีสกุลนี้ → route ตอบ 400 · `fallback` ล้มครบ → route ตอบ **200** พร้อมราคาบาทเดิมและ `fallback: true` |

**สาธิตจริง (2026-10-28):** ปกติ 890 บาท → 26.35 USD · สกุล `XXX` → 400 "ไม่รองรับสกุลเงิน" · รูปแบบผิด `US` → 400 · สินค้าไม่มี → 404 · จำลอง API ล่ม (ชี้ URL ผิด) → log: ลอง 3 ครั้ง รอ ~403 ms และ ~558 ms แล้ว fallback ใช้เวลารวม ~1.1 วินาที ผู้ใช้ได้ราคาบาทไม่เห็นหน้า error

**ข้อจำกัดที่ควรรู้ (ถ้าอาจารย์ถาม):** ถ้า API ภายนอก "ค้างไม่ตอบ" แต่ละครั้งรอเต็ม 3 วินาที สามครั้งรวม ~10 วินาทีกว่าจะ fallback (กรณีต่อไม่ติดจะเร็วกว่ามาก) แก้ได้ด้วยลด `EXTERNAL_API_TIMEOUT_MS`/`EXTERNAL_API_MAX_RETRIES` ใน `.env`

**🎯 endpoint:** `GET /api/v1/products/:id/price?currency=USD` · เปิดสาธารณะ · 200 (`price_thb, currency, rate, converted_price, fallback`) / 400 / 404
