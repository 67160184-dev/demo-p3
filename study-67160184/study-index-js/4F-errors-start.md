## 3 ส่วน

| บรรทัด | ทำอะไร |
|---|---|
| 464-468 | **404** — คำขอที่ไม่ตรงกับ endpoint ใดเลย ตกมาที่นี่ ตอบ `{ code: "NOT_FOUND", message: "ไม่พบเส้นทางที่ร้องขอ" }` |

## ทำไมต้องอยู่ท้ายสุด
Express ไล่หา endpoint จากบนลงล่าง ถ้า 404 อยู่บนสุด ทุกคำขอจะตกที่ 404 หมด จึงต้องวางหลัง endpoint ทั้งหมด

## ตัวจัดการ error รู้ได้ยังไงว่าเป็นตัวจัดการ error
ฟังก์ชันมี **4 ช่อง** `(err, req, res, next)` (บรรทัด 471) Express จำได้ว่าอันนี้รับ error โดยเฉพาะ เมื่อที่ไหนเรียก `next(err)` จะข้ามมาที่นี่ทันที

```
endpoint ไหนก็ได้ → catch (err) { next(err); } → บรรทัด 471 → 500
```

## บรรทัด 483 `if (require.main === module)`
- จริง = รันไฟล์นี้ตรงๆ (`npm start` → `node src/index.js`) → เปิดพอร์ต 3000
- เท็จ = ถูกไฟล์อื่น `require` (เช่น test) → ไม่เปิดพอร์ต test ใช้ Supertest ยิงแอปโดยตรง จึงรัน test ได้แม้เซิร์ฟเวอร์จริงเปิดอยู่ ไม่ชนพอร์ต
- บรรทัด 489 `module.exports = app` เปิดให้ test หยิบแอปไปใช้

## 🎯 คำถามที่อาจารย์น่าถาม + คำตอบสั้น

| คำถาม | คำตอบ |
|---|---|
| **error ที่ไม่คาดคิดจัดการยังไง** | ทุก endpoint มี `try/catch` ส่งต่อด้วย `next(err)` มาจบที่ตัวจัดการกลางบรรทัด 471 ตอบ 500 ไม่ทำให้เซิร์ฟเวอร์ล่ม |
| **เรียก path ที่ไม่มีได้อะไร** | 404 จากบรรทัด 464 |
| **test รันยังไงโดยไม่ต้องเปิดเซิร์ฟเวอร์** | `module.exports = app` + `listen` เฉพาะตอนรันตรง (บรรทัด 483) Supertest เรียกแอปตรงๆ ใช้ฐานข้อมูลแยก `product_db_test` |
| **endpoint ไหนยังไม่มี test** | บรรทัด `next(err)` ส่วนใหญ่ (เกิดเฉพาะตอนฐานข้อมูลล่มกลางทาง จำลองยาก) และ `app.listen` (484-485) — ดู `coverage-report.md` (coverage 94.23%) |
