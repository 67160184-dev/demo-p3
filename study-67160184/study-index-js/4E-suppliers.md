## จุดที่ต่างจากหมวดหมู่
- GET (383-387) `COUNT(p.id)` + `LEFT JOIN products ON p.supplier_id = s.id` + `GROUP BY s.id` แบบเดียวกัน
- PATCH แก้ได้ 4 ช่อง `SUPPLIER_EDITABLE_FIELDS = ["supplier_code", "name", "email", "phone"]` (บรรทัด 414)
- POST (441-446) `phone || null` = ไม่ส่งเบอร์ เก็บเป็นค่าว่าง (เบอร์ไม่บังคับ)
- `supplier_code` ส่งมาจากหน้าเว็บ (ถ้าเว้นว่าง หน้าเว็บสร้าง `SUP-` + เลขเวลาให้)

## 🎯 คำถามที่อาจารย์น่าถาม + คำตอบสั้น

| คำถาม | คำตอบ |
|---|---|
| **ลบผู้จัดจำหน่ายแล้วสินค้าเป็นยังไง** | สินค้า **ยังอยู่** แต่ช่องผู้จัดจำหน่ายกลายเป็นว่าง เพราะ FK ตั้ง `ON DELETE SET NULL` (ต่างจากหมวดหมู่ที่ CASCADE) |
| **ทำไมหมวดหมู่ CASCADE แต่ผู้จัดจำหน่าย SET NULL** | สินค้าต้องมีหมวดหมู่เสมอ ถ้าหมวดหายสินค้าก็ไม่มีที่อยู่ · ส่วนผู้จัดจำหน่ายเลิกส่งของได้ แต่สินค้าในคลังยังต้องอยู่ |
| **อะไรห้ามซ้ำ** | `supplier_code` และ `email` (UNIQUE) ส่วน `name` ซ้ำได้ เพราะมีรหัส/อีเมลระบุตัวแล้ว |
| **ทำไมผู้จัดจำหน่ายมีรหัส** | โจทย์ Phase 1 กำหนด (requirement.md) เป็นรหัสอ้างอิงที่คนอ่านได้ ต่างจาก `id` ที่ระบบใช้เชื่อมตาราง |
| **ผู้จัดจำหน่ายบังคับเลือกไหม** | หน้าเว็บบังคับเลือกตอนเพิ่ม/แก้สินค้า แต่ API รับ `null` ได้ เพื่อรองรับ SET NULL (ข้อจำกัดที่รู้อยู่) |
