# 5E — ข้อมูลตัวอย่าง + `deleteRequest` (app.js 331-462)

> [← ภาพรวม](00-overview.md) · โค้ด: [../frontend/app.js:331](../frontend/app.js) · ส่วนช่วย demo (อาจารย์ไม่ค่อยถาม)

## ทำอะไร
ปุ่ม "ใส่ข้อมูลตัวอย่าง" ในฟอร์มเพิ่ม เติมข้อมูลให้ ไว้ใช้ตอน demo ถ้าคิดข้อมูลไม่ออก

| บรรทัด | ชื่อ | ทำอะไร |
|---|---|---|
| 331-332 | `EMAIL_PATTERN`, `PHONE_PATTERN` | regex ตรวจอีเมล / เบอร์ (ใช้ในฟอร์มผู้จัดจำหน่าย) |
| 336 | `SAMPLE_PRODUCTS` | ~38 สินค้าตัวอย่าง แต่ละชิ้นมีคำค้น `category` / `supplier` บอกว่าเข้ากับหมวด/ผู้จัดจำหน่ายแบบไหน |
| 375, 383 | `SAMPLE_CATEGORIES`, `SAMPLE_SUPPLIERS` | 6 คู่ที่เข้ากัน (Sports↔SportGear ฯลฯ) |
| 393 | `findByKeywords` | หาหมวด/ผู้จัดจำหน่ายในระบบที่ชื่อมีคำค้น |
| 402 | `nextSku(category)` | สร้าง SKU รูปแบบเดิม `SKU-ELE-005` (อักษร 3 ตัวแรกของหมวด + เลขถัดไป) |
| 410 | `nextProductSample` | เลือกสินค้าที่ยังไม่มีชื่อซ้ำ + หมวดและผู้จัดจำหน่ายที่เข้ากัน (ไม่มีคู่ที่เข้ากัน → เว้นว่างให้เลือกเอง) |
| 436-455 | `nextUniqueSample` ฯลฯ | ตัวอย่างหมวด/ผู้จัดจำหน่ายที่ชื่อ/อีเมลยังไม่มีในระบบ (ฐานข้อมูลห้ามซ้ำ) |
| 458-462 | **`deleteRequest(url)`** | ใช้ร่วมกันทุกปุ่มลบ: toast "กำลังลบ..." → `apiFetch(DELETE)` → ผิดพลาดโยน error |

## ถ้าถูกถาม
- **ข้อมูลตัวอย่างสุ่มมั่วไหม?** → ไม่ สินค้าได้หมวดและผู้จัดจำหน่ายที่เข้ากัน เช่น แก้วกาแฟ → Home & Kitchen + SmartHome และ SKU ตามรูปแบบเดิม ตรวจแล้วบันทึกจริง 12 ชิ้นตรงกันทุกชิ้น
- **ส่งผลกับข้อมูลจริงไหม?** → แค่เติมช่องในฟอร์ม ผู้ใช้ต้องกด "เพิ่ม" เองถึงจะบันทึก
