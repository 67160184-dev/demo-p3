## ทำไมมีฟังก์ชันเดียว
ฟอร์มทุกแบบในระบบ (เพิ่ม/แก้ไข สินค้า หมวดหมู่ ผู้จัดจำหน่าย + ล็อกอิน + เปลี่ยนรหัส = 8 แบบ) เรียก **`openForm()`** ตัวเดียว ต่างกันแค่ "มีช่องอะไร" กับ "บันทึกแล้วทำอะไร" ลดโค้ดซ้ำ

```js
openForm({ title, fields, values, submitLabel, onSubmit, extra, busyText, failText })
```
| พารามิเตอร์ | ความหมาย |
|---|---|
| `fields` | รายการช่อง `{ key, label, type, required, check }` |
| `values` | ค่าเดิม (ตอนแก้ไข) |
| `onSubmit(values)` | ยิง API จริง ถ้าพังต้อง `throw` |
| `extra` | มีปุ่ม "ใส่ข้อมูลตัวอย่าง" + "ล้างฟอร์ม" (เฉพาะฟอร์มเพิ่ม) |

## 🎯 ตรวจข้อมูล (บรรทัด 299-311)

```js
for (const { f, input, error } of inputs) {
  const value = input.value.trim();                              // ตัดช่องว่างหัวท้าย
  if (f.required && value === "") problem = "กรุณากรอก/เลือก...";  // 304 ช่องบังคับว่าง
  else if (value !== "" && f.check) problem = f.check(value);      // 305 กฎเฉพาะช่อง
  error.textContent = problem || "";                               // ข้อความใต้ช่อง
  input.classList.toggle("invalid", Boolean(problem));             // กรอบแดง
}
if (firstInvalid) return firstInvalid.focus();                     // 311 มีช่องผิด → หยุด ไม่ยิง API
```

## 🎯 คำถามที่อาจารย์น่าถาม

| คำถาม | คำตอบ |
|---|---|
| **ตรวจข้อมูลที่หน้าเว็บอย่างเดียวพอไหม** | ไม่พอ ใครก็ข้ามหน้าเว็บได้ (Postman/Swagger) ฝั่ง backend มีกฎฐานข้อมูล (NOT NULL, CHECK, UNIQUE, FK) เป็นด่านสุดท้าย · ตามจริง: POST ของ backend ไม่ตรวจช่องเอง ข้อมูลผิดจึงได้ 500 ไม่ใช่ 400 (ข้อจำกัด) |
| **ตรวจผิดแล้วยิง API ไหม** | ไม่ยิง หยุดที่บรรทัด 311 แสดงกรอบแดงทุกช่องที่ผิดพร้อมกัน |
| **ทำไมใส่ `novalidate` ที่ form** | ปิดการตรวจของเบราว์เซอร์ (ข้อความอังกฤษ) ใช้ของเราแทน ภาษาไทยและบอกรายช่อง |
| **บันทึกพังแล้วผู้ใช้ต้องกรอกใหม่ไหม** | ไม่ต้อง ป๊อปอัปไม่ปิด ข้อมูลยังอยู่ แก้แล้วกดใหม่ได้ |
