### ลืมรหัสผ่าน admin? ตั้งใหม่ตรงนี้

เปิด Docker/MySQL แล้วเปิด PowerShell ในโฟลเดอร์ `project-phase3-67160184` จากนั้นเปลี่ยน `NewPass123` ในคำสั่งข้างล่างเป็นรหัสใหม่ที่ต้องการ (อย่างน้อย 8 ตัว):

```powershell
node -e "const b=require('bcrypt'),p=require('./src/db');b.hash('NewPass123',10).then(h=>p.query('UPDATE users SET password_hash=? WHERE email=?',[h,'admin@stockpro.com'])).then(r=>{console.log('updated',r[0].affectedRows);process.exit()})"
```

ถ้าขึ้น `updated 1` แปลว่าสำเร็จ ให้เข้าสู่ระบบด้วยรหัสใหม่ได้เลย ไม่ต้องรีสตาร์ทเซิร์ฟเวอร์ **ถ้าล้างข้อมูล demo ตามหัวข้อ 6 ภายหลัง รหัสจะกลับเป็นรหัสเริ่มต้น**

## 2. ติดตั้งครั้งแรก

### 2.1 ติดตั้งแพ็กเกจ
```bash
npm install
```

### 2.2 ตั้งค่าฐานข้อมูลในไฟล์ `.env`
ไฟล์ `.env` ในโฟลเดอร์นี้ตั้งค่าไว้แล้ว ถ้าไม่มี ให้คัดลอก `.env.example` เป็น `.env` แล้วแก้ 3 บรรทัด:

```
DB_PORT=3307
DB_PASSWORD=1234
JWT_SECRET=<ค่าสุ่มยาวๆ>
```

สร้างค่า `JWT_SECRET` ด้วยคำสั่งนี้ แล้วคัดลอกผลลัพธ์ไปวาง (ถ้าไม่ตั้ง ระบบยังรันได้ด้วยค่าสำรองสำหรับทดสอบ แต่ไม่ปลอดภัย):

```bash
node -e "console.log(require('crypto').randomBytes(64).toString('hex'))"
```

**ทำไมเป็น 3307?** พอร์ตมาตรฐานของ MySQL คือ 3306 แต่เครื่องนี้มีโปรเจกต์อื่นใช้ 3306 อยู่ container ของ StockPro (`stockpro_mysql_test`) จึงเปิดที่ 3307 — ถ้าตั้งผิดพอร์ต ระบบจะต่อฐานข้อมูลไม่ได้

ค่าอื่นใน `.env` ใช้ตามเดิมได้เลย:

| ตัวแปร | ความหมาย |
|---|---|
| `PORT` | พอร์ตของเซิร์ฟเวอร์ (3000) |
| `DB_HOST` `DB_USER` `DB_PASSWORD` `DB_NAME` `DB_PORT` | การเชื่อมต่อ MySQL |
| `EXCHANGE_API_URL` | ที่อยู่ API อัตราแลกเปลี่ยน (ใช้กับ `/products/:id/price`) |
| `EXTERNAL_API_TIMEOUT_MS` / `_MAX_RETRIES` / `_BACKOFF_MS` | timeout / จำนวนครั้งที่ลองใหม่ / เวลารอระหว่างลอง |
| `JWT_SECRET` / `JWT_EXPIRES_IN` | กุญแจลงลายเซ็น token ตอน login / อายุ token (ค่าเริ่มต้น `1h` = 1 ชั่วโมง หมดแล้วต้อง login ใหม่) |

**ถ้าเพิ่งอัปเดตเป็นเวอร์ชันที่มี login:** ต้องล้างข้อมูลตามหัวข้อ 6 หนึ่งครั้ง เพื่อสร้างตาราง `users` และบัญชี admin

### 2.3 (ทางเลือก) ถ้าต้องสร้าง container ฐานข้อมูลใหม่เอง
ใช้เมื่อเครื่องไม่มี `stockpro_mysql_test`:
```bash
docker compose up -d
```
จะสร้าง container ชื่อ `mysql_db` ที่พอร์ต **3306** และสร้างตารางจาก `schema.sql` ให้เอง (ยังไม่มีข้อมูล) — ต้องแก้ `.env` เป็น `DB_PORT=3306` แล้วใส่ข้อมูลตั้งต้นตามหัวข้อ 6 (ต้องใช้พอร์ต 3306 ว่าง และเปลี่ยนชื่อ container ในคำสั่งเป็น `mysql_db`)

### 2.4 (ทางเลือก) ตั้งรหัสเริ่มต้นของ admin เอง

**รหัสเริ่มต้น** คือรหัสที่ admin ได้ตอนติดตั้งครั้งแรก (ตอนนี้คือ `admin@stockpro.com1`) เก็บไว้ใน `seed.sql` แบบ bcrypt hash (ไม่เก็บรหัสจริง)

> **ถ้าแค่อยากใช้รหัสของตัวเองบนเครื่องนี้ ไม่ต้องทำหัวข้อนี้** — เข้าหน้าเว็บ → **👤 บัญชี → เปลี่ยนรหัสผ่าน** ได้เลย (แต่ล้างข้อมูลตามหัวข้อ 6 แล้วจะกลับเป็นรหัสเริ่มต้น)
> ทำหัวข้อนี้เมื่ออยากให้**เครื่องใหม่ที่ติดตั้งจากซิป** (เช่น เครื่องอาจารย์) ได้รหัสเริ่มต้นตามที่ตั้งเอง

ตัวอย่างใช้รหัส `MyPass2026` — เปลี่ยนเป็นรหัสที่ต้องการ (**อย่างน้อย 8 ตัว** และ**อย่าใช้รหัสของบัญชีจริงอื่น** เพราะ README นี้ใครเปิดก็เห็น) ทุกคำสั่งรันในโฟลเดอร์ `project-phase3-67160184`

**ขั้นที่ 1 — สร้าง hash ของรหัสใหม่**
```bash
node -e "require('bcrypt').hash('MyPass2026',10).then(console.log)"
```
ได้ข้อความขึ้นต้นด้วย `$2b$10$...` ยาวประมาณ 60 ตัว → คัดลอกไว้ (รันซ้ำได้ค่าไม่เหมือนเดิมเป็นเรื่องปกติ ใช้ได้ทุกอัน)

**ขั้นที่ 2 — แก้ `seed.sql`** (ส่วน `0. บัญชีผู้ดูแลระบบ`)
- บรรทัดที่ขึ้นต้น `('admin@stockpro.com', '$2b$10$...', 'admin')` → แทนข้อความ `$2b$10$...` ระหว่างเครื่องหมาย `' '` ด้วย hash ใหม่ (ให้ `'` ยังอยู่ครบ)
- บรรทัดคอมเมนต์ด้านบน `-- ... รหัสผ่านเริ่มต้น admin@stockpro.com1` → แก้เป็นรหัสใหม่ (จะได้จำได้)

**ขั้นที่ 3 — แก้ test ให้ตรง แล้วรันเช็ก**
- เปิด `src/__tests__/api.test.js` บรรทัด `const ADMIN = { email: "admin@stockpro.com", password: "admin@stockpro.com1" };` → เปลี่ยน `admin@stockpro.com1` เป็นรหัสใหม่
- รัน `npm test` ต้องได้ `Tests: 52 passed` — ถ้า fail ส่วนใหญ่เพราะ hash ในขั้น 2 ไม่ได้มาจากรหัสเดียวกับขั้น 3 (ทำขั้น 1 ใหม่)

**ขั้นที่ 4 — ให้เครื่องนี้ใช้รหัสเริ่มต้นใหม่ด้วย:** ล้างข้อมูลตามหัวข้อ 6 (ข้อมูลสินค้า/หมวดหมู่/ผู้จัดจำหน่ายที่เพิ่มไว้จะหาย) จากนั้น login ด้วยรหัสใหม่ในขั้นที่ 1; `seed.sql` จะตั้งรหัส admin ให้ตรงกับ hash ใหม่

**ขั้นที่ 5 — แก้เอกสารให้ตรง:** ค้นคำว่า `admin@stockpro.com1` ใน `README.md` และ `swagger-guide.md` แล้วแทนด้วยรหัสใหม่ (VS Code: `Ctrl+H` ค้นหาและแทนที่)

**ถ้าแก้แล้วต้องส่งงาน:** ทำซิปใหม่ เพราะ `seed.sql` และ `src/__tests__/api.test.js` อยู่ในซิป

## 4. วิธีใช้หน้าเว็บ

แถบสีน้ำเงินด้านบนมี **3 เมนู**: **สินค้า** · **หมวดหมู่** · **ผู้จัดจำหน่าย** (ตัวเลขข้างเมนู = จำนวนรายการ, รีเฟรชแล้วยังอยู่เมนูเดิม)

**สิทธิ์การใช้งาน — มี 2 โหมด:**

| โหมด | ทำอะไรได้ | หน้าจอ |
|---|---|---|
| **ผู้เยี่ยมชม** (ยังไม่ login) | ดูตารางและค้นหาได้อย่างเดียว | แถบสีฟ้าอ่อน "กำลังดูแบบผู้เยี่ยมชม" ด้านบน · ไม่มีปุ่มเพิ่ม/แก้ไข/ลบ |
| **ผู้ดูแลระบบ (admin)** | ดู ค้นหา เพิ่ม แก้ไข ลบ ได้ทั้งหมด | มุมขวาบนเป็นปุ่ม **👤 บัญชี ▾** กดแล้วเห็นอีเมล admin, **เปลี่ยนรหัสผ่าน**, **ออกจากระบบ** |

- **เข้าสู่ระบบ:** กด **🔑 เข้าสู่ระบบ** มุมขวาบน → อีเมล `admin@stockpro.com` รหัสผ่าน `admin@stockpro.com1` → กด **เข้าสู่ระบบ** (รหัสผิดจะขึ้นข้อความสีแดงในป๊อปอัป)
- **เปลี่ยนรหัสผ่าน:** กด **👤 บัญชี** → **🔒 เปลี่ยนรหัสผ่าน** → ใส่รหัสปัจจุบัน + รหัสใหม่ (อย่างน้อย 8 ตัวอักษร) 2 ครั้ง → **เปลี่ยนรหัสผ่าน** · ใช้รหัสใหม่ได้จนกว่าจะเปลี่ยนอีกครั้งหรือ **ล้างข้อมูลตามหัวข้อ 6 ซึ่งจะตั้งกลับเป็นรหัสเริ่มต้น** (อยากเปลี่ยนรหัสเริ่มต้น ดูหัวข้อ 2.4)
- รีเฟรชหน้าแล้วยัง login อยู่ (จำ token ไว้ในเบราว์เซอร์) จนกว่าจะกด **บัญชี → ออกจากระบบ** หรือ token หมดอายุ (1 ชั่วโมง) — ถ้าหมดอายุตอนกำลังบันทึก ระบบจะขึ้นข้อความให้ login ใหม่และกลับเป็นโหมดผู้เยี่ยมชม
- มีบัญชีเดียวคือ admin ไม่มีหน้าสมัครสมาชิก (บัญชีสร้างไว้ใน `seed.sql` รหัสผ่านเก็บเป็น bcrypt hash)

**ทุกเมนูใช้แบบเดียวกัน (ตอน login เป็น admin):**
1. ปุ่มสีน้ำเงิน **＋ เพิ่ม...** มุมขวาบน → เปิด**หน้าต่างป๊อปอัป**ฟอร์ม
2. ตารางรายการ แต่ละแถวมีปุ่ม **แก้ไข** (เปิดป๊อปอัปฟอร์มพร้อมข้อมูลเดิม) และ **ลบ** (สีแดง มีกล่องถามยืนยันก่อน)
3. ในป๊อปอัป: ช่องที่มี \* ต้องกรอก · กรอกผิดจะเป็นกรอบแดงพร้อมข้อความใต้ช่อง · กด **บันทึก/เพิ่ม** หรือ **Enter** · กด **ยกเลิก** หรือ **Esc** เพื่อปิด
4. **ป๊อปอัปเพิ่มข้อมูลทุกอัน** (สินค้า/หมวดหมู่/ผู้จัดจำหน่าย) มีลิงก์ล่างซ้าย:
   - **ใส่ข้อมูลตัวอย่าง** → กรอกให้ครบทุกช่องทันที กดซ้ำได้ชุดใหม่ (สินค้า 6 ชุด, หมวดหมู่ 6 ชุด, ผู้จัดจำหน่าย 5 ชุด) และเลือกชื่อ/อีเมลที่ยังไม่มีในระบบให้เอง จึงกดเพิ่มได้เลยไม่ติดข้อมูลซ้ำ — ใช้ตอน demo ถ้าคิดข้อมูลไม่ออก
   - **ล้างฟอร์ม** → ลบทุกช่องให้ว่าง (และลบข้อความเตือน) เพื่อกรอกเองใหม่
5. ผลลัพธ์ขึ้นเป็นแถบข้อความเล็กๆ มุมล่างของจอแล้วหายเอง

**ข้อความที่จะเจอ:**
- แถบมุมล่างสีเทาเข้ม มี ✓ = สำเร็จ (หายเองใน 3-4 วินาที)
- ตัวหนังสือสีแดงในป๊อปอัป หรือแถบมุมล่างสีแดง = ผิดพลาด เช่น ข้อมูลซ้ำ หรือเชื่อมต่อเซิร์ฟเวอร์ไม่ได้ (ป๊อปอัปไม่ปิด แก้แล้วกดบันทึกใหม่ได้)

**ข้อควรรู้:**
- เลข **ID ไม่ต่อเนื่อง** เป็นเรื่องปกติของ MySQL (`AUTO_INCREMENT` ไม่คืนเลขที่ INSERT ล้มเหลวไปแล้ว)
- ตัวเลือกหมวดหมู่/ผู้จัดจำหน่ายในฟอร์มสินค้าดึงจากฐานข้อมูลจริงทุกครั้ง (เพิ่ม/ลบแล้วอัปเดตเอง)
- ป้องกันที่ **backend** ด้วย ไม่ใช่แค่ซ่อนปุ่ม — ถ้ายิง POST/PATCH/DELETE โดยไม่มี token จะได้ 401 และข้อมูลไม่เปลี่ยน

**PowerShell:**
```powershell
$OutputEncoding = [System.Text.UTF8Encoding]::new($false)  # ส่งภาษาไทยเข้า Docker เป็น UTF-8
Get-Content schema.sql, seed.sql -Encoding UTF8 | docker exec -i stockpro_mysql_test mysql -uroot -p1234 --default-character-set=utf8mb4
```

บรรทัด `$OutputEncoding` สำคัญโดยเฉพาะ PowerShell รุ่นเก่า: ถ้าไม่ตั้งค่า ข้อความภาษาไทยที่ส่งผ่าน `|` อาจกลายเป็น `?` แม้ `Get-Content` อ่านไฟล์ UTF-8 ถูกต้องแล้ว

**Git Bash:**
```bash
cat schema.sql seed.sql | docker exec -i stockpro_mysql_test mysql -uroot -p1234 --default-character-set=utf8mb4
```

## 7. ลำดับ Demo สด (3-4 นาที)

ก่อนเริ่ม: ล้างข้อมูล (หัวข้อ 6) → ตรวจ `docker ps` → `npm start` → เปิดหน้าเว็บ

1. เปิดหน้าเว็บ (ยังไม่ login) → ตารางขึ้นเอง ไม่มีปุ่มเพิ่ม/แก้ไข/ลบ "นี่คือ `GET` ที่ดึงข้อมูลจาก 3 ตาราง (UC-04) ผู้เยี่ยมชมดูได้อย่างเดียว"
   → กด **🔑 เข้าสู่ระบบ** → ลองรหัสผิดก่อนให้เห็น error → กรอกบัญชี admin → ปุ่มเพิ่ม/แก้ไข/ลบโผล่ "login ได้ JWT แนบไปกับทุกคำขอที่แก้ข้อมูล"
2. กด **แก้ไข** แถว ID 1 → ป๊อปอัปขึ้น → เปลี่ยนราคา → **บันทึกการแก้ไข** → แถบ "✓ บันทึกการแก้ไข..." มุมล่าง "นี่คือ `PATCH` (UC-05)"
3. **เพิ่มสินค้า**: กด **＋ เพิ่มสินค้า** → กด **เพิ่มสินค้า** ตอนว่างให้เห็นช่องแดง → กรอกชื่อ, ราคา, สต็อก, เลือกหมวดหมู่/ผู้จัดจำหน่าย → เพิ่ม → แถวไฮไลต์สีฟ้า "`POST` (UC-03) ตรวจข้อมูลฝั่ง frontend ก่อนส่ง"
4. กดเมนู **หมวดหมู่** → **＋ เพิ่มหมวดหมู่** `Sports` (UC-01) · เมนู **ผู้จัดจำหน่าย** → **＋ เพิ่มผู้จัดจำหน่าย** (UC-02) · กลับเมนู **สินค้า** → เพิ่มสินค้าในหมวดนั้น "ครบ 5 Use Case ของ Phase 1"
5. **ลบ**: กด "ลบ" ที่สินค้าที่เพิ่งเพิ่ม → กล่องยืนยัน → OK → แถวหาย "`DELETE` พร้อมยืนยันก่อนลบ" (ถ้ามีเวลา: ลบหมวดหมู่ `Sports` ให้เห็นคำเตือนจำนวนสินค้าที่จะถูกลบตาม — foreign key `ON DELETE CASCADE`)
6. **แสดงราคาเป็น USD** (แถบเหนือตาราง) → ราคาทุกแถวเปลี่ยน + บรรทัดอัตรา → กด **บาท** กลับ "นี่คือ API ภายนอก open.er-api.com มี timeout/retry/fallback ถ้าล่มระบบไม่พัง"
7. กด **👤 บัญชี** → **ออกจากระบบ** → กลับเป็นโหมดดูอย่างเดียว
8. (ถ้ามีเวลา) เปิด http://localhost:3000/api-docs ลอง `DELETE` โดยไม่ Authorize ให้เห็น 401 หรือรัน `npm test`

**ขั้นตอนข้างบนคือสรุป "สิ่งที่ต้องกด"** — วันจริงใช้ **[presentation-script.md](presentation-script.md)** ซึ่งมีทั้งสิ่งที่ต้องกด สิ่งที่ต้องพูด และเวลาของแต่ละขั้น (คำตอบคำถามอาจารย์ฉบับเต็มอยู่ใน [defense-prep.md](defense-prep.md) หัวข้อ 3)

## 8. API ทั้งหมด (ตรงกับ `openapi.yaml`)

🔒 = ต้องแนบ token ของ admin (`Authorization: Bearer <token>`) ไม่แนบได้ **401**, token ถูกแต่ไม่ใช่ admin ได้ **403** · GET ทุกตัวไม่ต้อง login

| Method | Path | ทำอะไร | ตอบกลับ |
|---|---|---|---|
| POST | `/api/v1/auth/login` | เข้าสู่ระบบ ได้ JWT | 200 / 400 / 401 (อีเมลหรือรหัสผ่านผิด) |
| GET | `/api/v1/auth/me` | ข้อมูลผู้ใช้จาก token (ต้องแนบ token) | 200 / 401 |
| PATCH | `/api/v1/auth/change-password` | เปลี่ยนรหัสผ่าน ส่ง `oldPassword`, `newPassword` (ต้องแนบ token) | 200 / 400 (สั้นกว่า 8 ตัว, ซ้ำของเดิม, ไม่ครบ) / 401 (รหัสเดิมผิด หรือไม่มี token) |
| GET | `/health` | ตรวจสถานะเซิร์ฟเวอร์ | 200 |
| GET | `/api/v1/products` | รายการสินค้า + หมวดหมู่ + ผู้จัดจำหน่าย | 200 |
| GET | `/api/v1/products/:id` | สินค้ารายชิ้น | 200 / 404 |
| POST 🔒 | `/api/v1/products` | เพิ่มสินค้า | 201 / 500 (SKU ซ้ำ) |
| PATCH 🔒 | `/api/v1/products/:id` | แก้ชื่อ/SKU/หมวดหมู่/ผู้จัดจำหน่าย/ราคา/สต็อก (ส่งเฉพาะช่องที่แก้ อย่างน้อย 1 ช่อง) | 200 / 400 (ไม่ส่งช่องใดเลย) / 404 / 500 (SKU ซ้ำ หรือหมวดหมู่/ผู้จัดจำหน่ายไม่มีอยู่) |
| DELETE 🔒 | `/api/v1/products/:id` | ลบสินค้า | 200 / 404 |
| GET | `/api/v1/products/:id/price?currency=USD` | ราคาแปลงสกุลเงิน (เรียก API ภายนอก + retry/timeout/fallback) | 200 / 400 / 404 |
| GET | `/api/v1/categories` | รายการหมวดหมู่ + จำนวนสินค้า | 200 |
| POST 🔒 | `/api/v1/categories` | เพิ่มหมวดหมู่ | 201 / 500 (ชื่อซ้ำ) |
| PATCH 🔒 | `/api/v1/categories/:id` | แก้ชื่อ/คำอธิบายหมวดหมู่ (ส่งเฉพาะช่องที่แก้) | 200 / 400 / 404 / 500 (ชื่อซ้ำ) |
| DELETE 🔒 | `/api/v1/categories/:id` | ลบหมวดหมู่ (สินค้าในหมวดถูกลบตาม) | 200 / 404 |
| GET | `/api/v1/suppliers` | รายการผู้จัดจำหน่าย + จำนวนสินค้า | 200 |
| POST 🔒 | `/api/v1/suppliers` | เพิ่มผู้จัดจำหน่าย | 201 / 500 (อีเมล/รหัสซ้ำ) |
| PATCH 🔒 | `/api/v1/suppliers/:id` | แก้ชื่อ/อีเมล/เบอร์/รหัสผู้จัดจำหน่าย (ส่งเฉพาะช่องที่แก้) | 200 / 400 / 404 / 500 (อีเมล/รหัสซ้ำ) |
| DELETE 🔒 | `/api/v1/suppliers/:id` | ลบผู้จัดจำหน่าย (สินค้าเหลืออยู่ ไม่มีผู้จัดจำหน่าย) | 200 / 404 |

ลอง API ได้โดยตรงที่ http://localhost:3000/api-docs (กด **Try it out** → **Execute**) — คู่มือละเอียดสำหรับมือใหม่ พร้อมแบบฝึก 13 ข้อ: **[swagger-guide.md](swagger-guide.md)** ✱ ระวัง: คำสั่ง POST/PATCH/DELETE ที่ลองจะเปลี่ยนข้อมูลจริง

**ลองคำสั่งที่มี 🔒 ใน Swagger:** เรียก `POST /api/v1/auth/login` ด้วยบัญชี admin → คัดลอกค่า `token` (ไม่ต้องมีเครื่องหมาย ") → กดปุ่ม **Authorize** สีเขียวด้านบน → วาง → **Authorize** → **Close** แล้วค่อย Try it out

| ขึ้น `Cannot find module '../db'` | หา `db.js` ที่ระดับบนของโปรเจกต์ไม่เจอ | ตรวจว่ามี `db.js` อยู่ข้าง `package.json` แล้ว `Ctrl+C` และ `npm start` ใหม่ |
| `ECONNREFUSED` ตอน `npm test` หรือ `npm start` | container ฐานข้อมูลไม่ได้รัน หรือ `DB_PORT` ใน `.env` ไม่ตรง (ต้อง 3307) | `docker ps` ตรวจ container และเปิด `.env` ตรวจ `DB_PORT=3307` |
| `Access denied for user 'root'` | `DB_PASSWORD` ใน `.env` ผิด | ตั้งเป็น `1234` |
| `Unknown database 'product_db'` หรือไม่มีตาราง | ฐานข้อมูลยังไม่ได้สร้าง | ทำตามหัวข้อ 6 |
| ตารางสินค้ารก มีสินค้าซ้ำๆ | เหลือข้อมูลจากการซ้อม | ล้างข้อมูลตามหัวข้อ 6 |
| หน้าเว็บไม่เปลี่ยนหลังแก้โค้ด | เบราว์เซอร์จำไฟล์เก่า | กด `Ctrl+F5` |
| ลบข้อมูลผิดตอนซ้อม | การลบย้อนกลับไม่ได้ | ล้างข้อมูลกลับเป็นตั้งต้นตามหัวข้อ 6 |
| กด "ลบ" แล้วไม่มีอะไรเกิดขึ้น หรือหน้าเว็บไม่มีปุ่มลบ | เซิร์ฟเวอร์ยังรันโค้ดเก่า หรือเบราว์เซอร์จำไฟล์เก่า | `Ctrl+C` แล้ว `npm start` ใหม่ จากนั้นกด `Ctrl+F5` |
| `docker ps` ไม่ขึ้นอะไรเลย | ไม่มี container ที่กำลังรัน | `docker ps -a` ดูทั้งหมด แล้ว `docker start stockpro_mysql_test` |
| login แล้วขึ้น "เกิดข้อผิดพลาดภายในเซิร์ฟเวอร์" (`Table 'product_db.users' doesn't exist`) | ฐานข้อมูลยังเป็นของเวอร์ชันก่อนมี login | ล้างข้อมูลตามหัวข้อ 6 หนึ่งครั้ง (สร้างตาราง `users` + บัญชี admin) |
| login ขึ้น "อีเมลหรือรหัสผ่านไม่ถูกต้อง" | พิมพ์ผิด หรือเคยเปลี่ยนรหัสผ่านไปแล้ว | รหัสเริ่มต้นคือ `admin@stockpro.com1` (พิมพ์ตัวเล็กตามตัวอย่าง) ถ้าเคยเปลี่ยนแล้วจำไม่ได้ ดู "ลืมรหัสผ่าน" ใต้ตารางนี้ |
| กดบันทึกแล้วขึ้น "Token ไม่ถูกต้องหรือหมดอายุ" แล้วถูกออกจากระบบ | token อายุครบ 1 ชั่วโมง หรือเปลี่ยน `JWT_SECRET` แล้วรีสตาร์ทเซิร์ฟเวอร์ | กด **เข้าสู่ระบบ** ใหม่ แล้วทำรายการเดิมอีกครั้ง |
| ไม่เห็นปุ่มเพิ่ม/แก้ไข/ลบ | ยังไม่ได้ login (โหมดผู้เยี่ยมชม) | กด **🔑 เข้าสู่ระบบ** มุมขวาบน |

**ลืมรหัสผ่าน admin:** ตั้งรหัสใหม่ด้วยคำสั่งนี้ในโฟลเดอร์ `project-phase3-67160184` (แก้ `NewPass123` เป็นรหัสที่ต้องการ อย่างน้อย 8 ตัว) ขึ้น `updated 1` = สำเร็จ ไม่ต้องรีสตาร์ทเซิร์ฟเวอร์:


## 11. ทดสอบหน้าเว็บอัตโนมัติ (E2E) — ลบสคริปต์ออกแล้ว

เคยมีสคริปต์ Playwright (`e2e-*.js`) ที่เปิดเบราว์เซอร์จริงแล้วกดทดสอบหน้าเว็บให้ — **ลบออกจากโฟลเดอร์แล้ว** ไม่กระทบระบบ ซิป หรือการ demo (ไม่เคยอยู่ในซิป)

ผลที่ทดสอบไว้ก่อนลบสคริปต์ (ก่อนเพิ่มฟีเจอร์แก้ไข/ลบ): ครบทุกฟังก์ชัน 46/46 ใน Edge จริง · หน้าเว็บไม่เพี้ยนที่ 11 ความกว้างจอ (320-1280px) · Swagger `/api-docs` 16/16
หลังเพิ่มฟีเจอร์แก้ไข/ลบ และจัดหน้าใหม่เป็นเมนู + ป๊อปอัปฟอร์ม (2026-10-25): ทดสอบในเบราว์เซอร์อีกรอบ — เพิ่ม/แก้ไข/ลบ ครบ 3 เมนูผ่านป๊อปอัป, ช่องค้นหา (ชื่อ/SKU/หมวดหมู่/ผู้จัดจำหน่าย และกรณีไม่พบ), แก้สินค้าได้ทุกช่อง (รวมย้ายหมวดหมู่/ผู้จัดจำหน่าย), แก้ไขหมวดหมู่และผู้จัดจำหน่าย (ชื่อซ้ำ/อีเมลผิดรูปแบบขึ้น error), ฟอร์มเพิ่มสินค้าบังคับเลือกผู้จัดจำหน่ายและกรอกสต็อก, SKU ซ้ำขึ้น error, ลบสินค้า, ลบหมวดหมู่ (สินค้าในหมวดหายตาม), ลบผู้จัดจำหน่าย (สินค้าเหลือ "-"), จอ 320px ไม่ล้น

ถ้าต้องการทดสอบซ้ำหลังแก้หน้าเว็บ ให้สั่งใหม่ว่า "เขียนสคริปต์ E2E ทดสอบหน้าเว็บใหม่" (ต้องมี `npm install --no-save playwright` และ `npx playwright install chromium`) ระหว่างนี้ใช้ขั้นตอนทดสอบด้วยมือในหัวข้อ 4 และ 7 แทนได้
