## login ทีละขั้น (บรรทัด 49-73)

```
50  หยิบ email, password จาก req.body
51  ไม่ครบ → 400 BAD_REQUEST
57  SELECT * FROM users WHERE email = ?        ← ค้นผู้ใช้
59  bcrypt.compare(รหัสที่พิมพ์, hash)           ← ไม่พบอีเมลก็เทียบกับ hash ปลอม (บรรทัด 47)
60  ไม่พบ หรือ รหัสผิด → 401 INVALID_CREDENTIALS (ข้อความเดียวกัน)
65  สำเร็จ → 200 { token: generateToken(user), user }   (ไม่ส่ง password_hash กลับ)
71  พังไม่คาดคิด → next(err) → 500
```

## /auth/me (บรรทัด 76-79)
มี `authenticateToken` คั่น → คืน `req.user` (ข้อมูลในบัตร) หน้าเว็บเรียกตอนเปิดหน้า เช็กว่าบัตรที่จำไว้ยังใช้ได้

## เปลี่ยนรหัสผ่าน (บรรทัด 84-109)

```
87-91  ตรวจ: ส่งครบ, ใหม่ ≥ 8 ตัว (MIN_PASSWORD_LENGTH บรรทัด 82), ไม่ซ้ำเดิม → ไม่ผ่าน 400
94     หาบัญชีจาก req.user.id (id ในบัตร ไม่ใช่ที่หน้าเว็บส่ง → แก้ได้แค่ของตัวเอง)
98     รหัสเดิมผิด → 401 INVALID_CREDENTIALS
103    bcrypt.hash(รหัสใหม่, 10)
104    UPDATE users SET password_hash = ? WHERE id = ?
105    200 สำเร็จ
```

## 🎯 คำถามที่อาจารย์น่าถาม + คำตอบสั้น

| คำถาม | คำตอบ |
|---|---|
| **รหัสผ่านเก็บยังไง** | เก็บเป็น bcrypt hash ไม่เก็บรหัสจริง ตอน login ใช้ `bcrypt.compare` (บรรทัด 59) |
| **ทำไมใช้ `?` ใน SQL** (บรรทัด 57) | กัน **SQL injection** ค่าที่ผู้ใช้ส่งถูกมองเป็นข้อความเสมอ ไม่ถูกรันเป็นคำสั่ง SQL |
| **ทำไม login ผิดตอบข้อความเดียวกัน** | ไม่บอกว่าผิดที่อีเมลหรือรหัส กันคนร้ายเดาว่าอีเมลไหนมีในระบบ |
| **ทำไมเทียบกับ hash ปลอมตอนไม่พบอีเมล** (บรรทัด 47, 59) | ให้ใช้เวลาเท่ากันทุกกรณี กัน **timing attack** (จับเวลาเดาอีเมล) |
| **token มีอะไร อายุเท่าไร** | `id, email, role` อายุ 1 ชั่วโมง เซ็นด้วย `JWT_SECRET` ใน `.env` |
| **401 กับ 403 ต่างกัน** | 401 ไม่รู้ว่าเป็นใคร (ไม่มี/เสีย token) · 403 รู้แต่ไม่มีสิทธิ์ |
| **แอบแก้ role ใน token ได้ไหม** | ไม่ได้ ลายเซ็นไม่ตรง `jwt.verify` ปฏิเสธ → 401 `INVALID_TOKEN` |
| **รหัสเดิมผิดตอนเปลี่ยนรหัส ทำไมไม่ถูกเตะออก** | ตอบ 401 รหัส `INVALID_CREDENTIALS` ไม่ใช่ `NO_TOKEN`/`INVALID_TOKEN` หน้าเว็บจึงไม่ออกจากระบบ |
| **มีกี่ role** | role เดียวคือ admin (ตาราง `users` ENUM('admin')) ไม่มีหน้าสมัครสมาชิก บัญชีสร้างใน `seed.sql` |
