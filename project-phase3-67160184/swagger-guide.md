## 0. Swagger คืออะไร

**Swagger UI** คือหน้าเว็บที่สร้างขึ้นอัตโนมัติจากไฟล์ `openapi.yaml` (เอกสาร API ของเรา) ทำหน้าที่ 2 อย่าง:

1. **เป็นคู่มือ API** — บอกว่าระบบมี endpoint อะไรบ้าง ต้องส่งข้อมูลอะไร และจะได้ผลลัพธ์แบบไหน
2. **เป็นที่ทดลองเรียก API จริง** — กดปุ่มแล้วระบบจะส่งคำขอไปที่เซิร์ฟเวอร์ของเราจริงๆ แล้วแสดงผลลัพธ์ให้ดู โดยไม่ต้องใช้ Postman หรือเขียนโค้ด

**เปรียบเทียบ:** เหมือน**เมนูร้านอาหารที่สั่งได้จากเมนูเลย** — อ่านรายการอาหาร (endpoint) รู้ว่าต้องเลือกอะไรบ้าง (ข้อมูลที่ต้องส่ง) แล้วกดสั่ง (Execute) จะได้อาหารจริง (ผลลัพธ์จริงจากเซิร์ฟเวอร์)

⚠️ **สำคัญ:** การลองใน Swagger **เปลี่ยนข้อมูลจริงในฐานข้อมูล** (เพิ่ม/แก้/ลบ จริง) ลองเสร็จให้ล้างข้อมูลตาม[หัวข้อ 8](#8-ลองเสร็จแล้ว-ล้างข้อมูลกลับเป็นตั้งต้น)

## 2. รู้จักหน้าจอ Swagger

ไล่จากบนลงล่าง:

```
┌─────────────────────────────────────────────────────────────┐
│ Swagger (โลโก้)                              💡 (สลับสีพื้น)  │
│                                                             │
│ StockPro - Product Management API  [1.0.0] [OAS 3.0]        │ ← ชื่อระบบ
│ คำอธิบายระบบ + สิทธิ์การใช้งาน                                  │
│                                                             │
│ Servers [http://localhost:3000 ▾]          [ Authorize 🔓 ]  │ ← ใส่ token ตรงนี้
├─────────────────────────────────────────────────────────────┤
│ Auth                                                    ^   │ ← กลุ่ม (tag)
│  [POST]   /api/v1/auth/login   เข้าสู่ระบบ...            ˅   │ ← 1 แถบ = 1 endpoint
│  [GET]    /api/v1/auth/me      ข้อมูลผู้ใช้...        🔒 ˅   │ ← 🔒 = ต้องใช้ token
│  [PATCH]  /api/v1/auth/change-password ...          🔒 ˅   │
│ Health                                                      │
│ Products                                                    │
│ Categories                                                  │
│ Suppliers                                                   │
│ Schemas  (ท้ายสุด — รูปแบบข้อมูล)                               │
└─────────────────────────────────────────────────────────────┘
```

### 2.1 แต่ละส่วนคืออะไร

| ส่วน | คืออะไร |
|---|---|
| **Servers** | เซิร์ฟเวอร์ที่ Swagger จะส่งคำขอไป ของเรามีอันเดียวคือ `http://localhost:3000` ไม่ต้องเปลี่ยน |
| **ปุ่ม Authorize** (สีเขียว มีรูปกุญแจ) | ที่ใส่ token หลัง login เพื่อใช้ endpoint ที่ต้องเป็น admin (ดู[แบบฝึกที่ 7](#แบบฝึกที่-7-กด-authorize-ใส่-token)) |
| **กลุ่ม (Auth, Health, Products, Categories, Suppliers)** | จัด endpoint ตามเรื่อง กดชื่อกลุ่มเพื่อพับ/กาง |
| **แถบสี 1 แถบ** | endpoint 1 ตัว = คำสั่ง 1 อย่างที่ระบบทำได้ |
| **รูปกุญแจ 🔒 ท้ายแถบ** | endpoint นี้**ต้อง login เป็น admin** ก่อน (กุญแจเปิด = ยังไม่ได้ใส่ token, กุญแจปิด = ใส่แล้ว) |
| **💡 มุมขวาบน** | สลับพื้นมืด/สว่าง ไม่มีผลกับการทำงาน |
| **Schemas** (ท้ายหน้า) | รูปแบบข้อมูลที่รับ/ส่ง (ดู[หัวข้อ 6](#6-ส่วน-schemas-ท้ายหน้า)) |

### 2.2 สีของแถบ = ชนิดคำสั่ง (HTTP Method)

| สี | Method | ความหมาย | ต้อง login? |
|---|---|---|---|
| 🔵 น้ำเงิน | **GET** | **ขอดู**ข้อมูล ไม่เปลี่ยนอะไร | ไม่ต้อง (ยกเว้น `/auth/me`) |
| 🟢 เขียว | **POST** | **สร้าง/เพิ่ม**ข้อมูลใหม่ | ต้อง (ยกเว้น `/auth/login`) |
| 🟦 เขียวอมฟ้า | **PATCH** | **แก้ไขบางช่อง**ของข้อมูลที่มีอยู่ | ต้อง |
| 🔴 แดง | **DELETE** | **ลบ**ข้อมูล | ต้อง |

### 2.3 endpoint ทั้งหมดของระบบ (18 ตัว)

| กลุ่ม | Method | Path | ทำอะไร |
|---|---|---|---|
| Auth | POST | `/api/v1/auth/login` | เข้าสู่ระบบ ได้ token |
| Auth | GET 🔒 | `/api/v1/auth/me` | ดูว่า token นี้เป็นของใคร |
| Auth | PATCH 🔒 | `/api/v1/auth/change-password` | เปลี่ยนรหัสผ่าน |
| Health | GET | `/health` | เช็กว่าเซิร์ฟเวอร์ทำงานอยู่ไหม |
| Products | GET | `/api/v1/products` | ดูสินค้าทั้งหมด |
| Products | POST 🔒 | `/api/v1/products` | เพิ่มสินค้า |
| Products | GET | `/api/v1/products/{id}` | ดูสินค้า 1 ชิ้นตาม ID |
| Products | PATCH 🔒 | `/api/v1/products/{id}` | แก้ไขสินค้า |
| Products | DELETE 🔒 | `/api/v1/products/{id}` | ลบสินค้า |
| Products | GET | `/api/v1/products/{id}/price` | แปลงราคาเป็นสกุลเงินอื่น (เรียก API ภายนอก) |
| Categories | GET | `/api/v1/categories` | ดูหมวดหมู่ทั้งหมด |
| Categories | POST 🔒 | `/api/v1/categories` | เพิ่มหมวดหมู่ |
| Categories | PATCH 🔒 | `/api/v1/categories/{id}` | แก้ไขหมวดหมู่ |
| Categories | DELETE 🔒 | `/api/v1/categories/{id}` | ลบหมวดหมู่ (สินค้าในหมวดถูกลบตาม!) |
| Suppliers | GET | `/api/v1/suppliers` | ดูผู้จัดจำหน่ายทั้งหมด |
| Suppliers | POST 🔒 | `/api/v1/suppliers` | เพิ่มผู้จัดจำหน่าย |
| Suppliers | PATCH 🔒 | `/api/v1/suppliers/{id}` | แก้ไขผู้จัดจำหน่าย |
| Suppliers | DELETE 🔒 | `/api/v1/suppliers/{id}` | ลบผู้จัดจำหน่าย |

`{id}` ใน path = **ช่องที่ต้องใส่เลข ID** เช่น `/api/v1/products/1` คือสินค้า ID 1

## 3. วิธีลองเรียก API (4 ขั้นที่ใช้ทุกครั้ง)

ทุก endpoint ใช้ขั้นตอนเดียวกัน:

### ขั้นที่ 1 — กดที่แถบเพื่อกางออก
กดที่ไหนก็ได้บนแถบ (เช่น ที่ข้อความ `/health`) แถบจะกางออก เห็นรายละเอียด:
- **Parameters** — ช่องที่ต้องใส่ใน URL (เช่น `id`) ถ้าไม่มีจะขึ้น "No parameters"
- **Request body** — ข้อมูล JSON ที่ต้องส่ง (มีเฉพาะ POST/PATCH)
- **Responses** — ผลลัพธ์ที่เป็นไปได้ (เป็นเอกสาร ยังไม่ใช่ผลจริง)

### ขั้นที่ 2 — กดปุ่ม **Try it out** (ขวาบนของแถบที่กาง)
ช่องต่างๆ จะเปลี่ยนเป็น**แก้ไขได้** และปุ่ม Try it out จะกลายเป็น **Cancel** (กดเพื่อเลิกลอง)

### ขั้นที่ 3 — ใส่/แก้ค่า (ถ้ามี)
- ช่อง **Parameters** เช่น `id` → พิมพ์ตัวเลขลงไป
- กล่อง **Request body** → Swagger เติม**ข้อมูลตัวอย่าง**ไว้ให้แล้ว แก้ได้เลย
  - ⚠️ ต้องเป็นรูปแบบ JSON ที่ถูกต้อง: มีปีกกา `{ }` ชื่อช่องและข้อความอยู่ใน `" "` ตัวเลขไม่ต้องมี `" "` คั่นแต่ละช่องด้วยลูกน้ำ `,` (ช่องสุดท้ายห้ามมีลูกน้ำ)
  - ทำพังแล้ว กดปุ่ม **Reset** กลับเป็นตัวอย่างเดิม

### ขั้นที่ 4 — กดปุ่มสีน้ำเงิน **Execute**
Swagger ส่งคำขอไปที่เซิร์ฟเวอร์จริง แล้วแสดงผลด้านล่าง (ดูหัวข้อถัดไป) กด **Clear** ข้างปุ่ม Execute เพื่อลบผลออก

## 4. อ่านผลลัพธ์ให้เป็น

หลังกด Execute จะมีส่วนใหม่ขึ้นมา เรียงจากบนลงล่าง:

| หัวข้อ | คืออะไร | ต้องดูไหม |
|---|---|---|
| **Curl** | คำสั่งเดียวกันในรูปแบบ command line (เอาไปรันใน terminal ได้) | ไม่จำเป็น |
| **Request URL** | URL จริงที่ถูกเรียก เช่น `http://localhost:3000/api/v1/products/1` | ดูว่า id ถูกไหม |
| **Server response → Code** | **รหัสสถานะ** ผลลัพธ์สำคัญที่สุด (ตารางด้านล่าง) | ✅ ดูเสมอ |
| **Server response → Response body** | ข้อมูลที่เซิร์ฟเวอร์ตอบกลับ (JSON) | ✅ ดูเสมอ |
| **Response headers** | ข้อมูลเสริมทางเทคนิค | ไม่จำเป็น |
| **Responses** (ด้านล่างสุด) | เอกสารบอกว่า endpoint นี้ตอบได้กี่แบบ — **ไม่ใช่ผลจริง** อย่าสับสน | ใช้อ่านประกอบ |

### รหัสสถานะ (Code) ที่จะเจอในระบบนี้

| Code | ความหมาย | ตัวอย่างในระบบนี้ |
|---|---|---|
| **200** ✅ | สำเร็จ | ดูข้อมูล, แก้ไข, ลบ, login สำเร็จ |
| **201** ✅ | สร้างข้อมูลใหม่สำเร็จ | เพิ่มสินค้า/หมวดหมู่/ผู้จัดจำหน่าย |
| **400** ⚠️ | ข้อมูลที่ส่งมาไม่ถูกต้อง | ไม่ส่งช่องที่ต้องใช้, รหัสสกุลเงินผิด, รหัสผ่านใหม่สั้นเกิน |
| **401** 🔒 | ยังไม่ login / token ผิดหรือหมดอายุ / รหัสผ่านผิด | กด DELETE โดยไม่ Authorize |
| **403** 🚫 | login แล้วแต่ไม่มีสิทธิ์ (ไม่ใช่ admin) | — (ระบบมีแต่ admin จึงไม่ค่อยเจอ) |
| **404** ❓ | หาไม่เจอ | ดูสินค้า ID ที่ไม่มี เช่น 99999 |
| **500** ❌ | เซิร์ฟเวอร์/ฐานข้อมูลปฏิเสธ | **ข้อมูลซ้ำ** เช่น SKU ซ้ำ, ชื่อหมวดหมู่ซ้ำ, อีเมลซ้ำ |

**จำง่ายๆ:** ขึ้นต้นด้วย **2 = สำเร็จ**, **4 = ฝั่งเราส่งผิด**, **5 = ฝั่งเซิร์ฟเวอร์/ฐานข้อมูลมีปัญหา**

### อ่าน Response body
ตัวอย่างผลของ `GET /api/v1/products/1`:

```json
{
  "message": "ดึงข้อมูลสินค้าสำเร็จ",      ← ข้อความสรุป
  "data": {                                ← ข้อมูลจริง
    "id": 1,
    "sku": "SKU-ELE-001",
    "product_name": "Wireless Ergonomic Mouse",
    "price": "890.00",
    "stock_quantity": 50,
    "category_id": 1,
    "category_name": "Electronics",       ← ได้จาก JOIN ตาราง categories
    "supplier_id": 1,
    "supplier_name": "TechSupply Co., Ltd." ← ได้จาก JOIN ตาราง suppliers
  }
}
```

ถ้าผิดพลาด จะได้รูปแบบเดียวกันทุก endpoint:

```json
{
  "error": {
    "code": "NOT_FOUND",              ← รหัสข้อผิดพลาด
    "message": "ไม่พบข้อมูลสินค้า"       ← ข้อความภาษาไทย
  }
}
```

## 5. แบบฝึกทีละขั้น (ทำตามลำดับ)

ทำตามลำดับ 1 → 13 จะได้ลองครบทุกแบบ ใช้เวลาประมาณ 15-20 นาที

### แบบฝึกที่ 1: เช็กว่าเซิร์ฟเวอร์ทำงาน (`GET /health`)
1. กลุ่ม **Health** → กดแถบ `GET /health`
2. กด **Try it out** → กด **Execute**
3. ✅ ต้องได้ **Code 200** และ body `{"status": "OK", "message": "Product API is running"}`

### แบบฝึกที่ 2: ดูสินค้าทั้งหมด (`GET /api/v1/products`)
1. กลุ่ม **Products** → แถบ `GET /api/v1/products` → **Try it out** → **Execute**
2. ✅ Code **200** body มี `"total": 3` และ `"data": [ ... ]` เป็นรายการสินค้า 3 ชิ้น
3. สังเกต: ไม่ต้อง login ก็ดูได้ (ไม่มีรูปกุญแจ)

### แบบฝึกที่ 3: ดูสินค้า 1 ชิ้น + กรณีหาไม่เจอ (`GET /api/v1/products/{id}`)
1. แถบ `GET /api/v1/products/{id}` → **Try it out**
2. ช่อง **id** พิมพ์ `1` → **Execute** → ✅ Code **200** ได้ Wireless Ergonomic Mouse
3. แก้ **id** เป็น `99999` → **Execute** → ✅ Code **404** `"code": "NOT_FOUND"`
4. 👉 นี่คือการโชว์ว่าระบบ**จัดการข้อผิดพลาด**ได้ ไม่พัง

### แบบฝึกที่ 4: แปลงราคาเป็นสกุลเงินอื่น (`GET /api/v1/products/{id}/price`)
1. แถบ `GET /api/v1/products/{id}/price` → **Try it out**
2. **id** = `1`, **currency** = `USD` → **Execute**
3. ✅ Code **200** มี `converted_price` (ราคาเป็นดอลลาร์) และ `"fallback": false`
   - ถ้าได้ `"fallback": true` = เรียก API อัตราแลกเปลี่ยนภายนอกไม่ได้ (เช่น เน็ตหลุด) ระบบเลยตอบเป็นราคาบาทแทน **ไม่พัง** — นี่คือ retry/timeout/fallback ของ Phase 2
4. ลอง **currency** = `XYZ` → ✅ Code **400** "ไม่รองรับสกุลเงิน XYZ"

### แบบฝึกที่ 5: ลองเพิ่มข้อมูลโดยยังไม่ login → โดนปฏิเสธ
1. กลุ่ม **Categories** → แถบ `POST /api/v1/categories` (มีรูปกุญแจ 🔓) → **Try it out** → **Execute**
2. ✅ Code **401** `"code": "NO_TOKEN"` ข้อความ "กรุณาเข้าสู่ระบบก่อนใช้งาน"
3. 👉 แปลว่า**ป้องกันที่ backend จริง** ไม่ใช่แค่ซ่อนปุ่มในหน้าเว็บ — ข้อมูลไม่ถูกเพิ่ม

### แบบฝึกที่ 6: Login เพื่อขอ token (`POST /api/v1/auth/login`)
1. กลุ่ม **Auth** → แถบ `POST /api/v1/auth/login` → **Try it out**
2. ในกล่อง **Request body** จะเห็นตัวอย่าง:
   ```json
   {
     "email": "admin@stockpro.com",
     "password": "string"
   }
   ```
   ⚠️ **`"string"` ไม่ใช่รหัสผ่านจริง** — ลบคำว่า `string` แล้วพิมพ์รหัสผ่าน admin แทน (อยู่ใน [README.md](README.md) หัวข้อ 0 — รหัสเริ่มต้นคือ `admin@stockpro.com1` ถ้าเคยเปลี่ยนไว้ให้ใช้รหัสใหม่ แต่หลังล้างข้อมูลตาม README หัวข้อ 6 ให้ใช้รหัสเริ่มต้น) ให้เหลือ:
   ```json
   {
     "email": "admin@stockpro.com",
     "password": "admin@stockpro.com1"
   }
   ```
3. กด **Execute** → ✅ Code **200** body มี `"token": "eyJhbGciOi....."` (ข้อความยาวมาก)
4. **คัดลอก token:**
   - ลากคลุม**เฉพาะตัวอักษรระหว่างเครื่องหมาย `"`** ตั้งแต่ `eyJ` จนถึงตัวสุดท้ายก่อน `"` → กด `Ctrl+C`
   - ❌ อย่าคัดลอกเครื่องหมาย `"` ติดมา และอย่าคัดลอกคำว่า `"token":`
   - token มีอายุ 1 ชั่วโมง เกินแล้วต้อง login ใหม่
5. (ลองผิด) แก้ password เป็นอย่างอื่น → Execute → ✅ Code **401** "อีเมลหรือรหัสผ่านไม่ถูกต้อง"

### แบบฝึกที่ 7: กด Authorize ใส่ token
1. เลื่อนขึ้นบนสุด กดปุ่มสีเขียว **Authorize 🔓**
2. หน้าต่าง **Available authorizations** จะเปิดขึ้น เห็น `bearerAuth (http, Bearer)`
3. ช่อง **Value:** → วาง token ที่คัดลอกมา (`Ctrl+V`) — **ไม่ต้องพิมพ์คำว่า Bearer** Swagger เติมให้เอง
4. กด **Authorize** → ปุ่มเปลี่ยนเป็น **Logout** แปลว่าใส่สำเร็จ
5. กด **Close** ปิดหน้าต่าง
6. ✅ สังเกต: รูปกุญแจทุกแถบเปลี่ยนเป็น**กุญแจปิด 🔒** และปุ่ม Authorize ด้านบนก็เป็นกุญแจปิด

### แบบฝึกที่ 8: เช็กว่า token ใช้ได้ (`GET /api/v1/auth/me`)
1. แถบ `GET /api/v1/auth/me` → **Try it out** → **Execute**
2. ✅ Code **200** body `"data": {"id": 1, "email": "admin@stockpro.com", "role": "admin"}`

### แบบฝึกที่ 9: เพิ่มหมวดหมู่ (`POST /api/v1/categories`)
1. แถบ `POST /api/v1/categories` → **Try it out**
2. แก้ Request body เป็น (ชื่อต้อง**ไม่ซ้ำ**ของที่มี — ระบบมี Electronics, Apparel, Home & Kitchen อยู่แล้ว):
   ```json
   {
     "name": "Sports",
     "description": "อุปกรณ์กีฬา"
   }
   ```
3. **Execute** → ✅ Code **201** body มี `"data": {"id": 4, "name": "Sports", ...}` → **จำเลข id ไว้** (ในตัวอย่างคือ 4)
4. กด **Execute** ซ้ำอีกครั้งโดยไม่แก้ → ✅ Code **500** เพราะชื่อหมวดหมู่ซ้ำ (ฐานข้อมูลตั้ง UNIQUE ไว้)
5. ไปที่แถบ `GET /api/v1/categories` → Try it out → Execute → เห็น Sports ในรายการ

### แบบฝึกที่ 10: เพิ่มสินค้า (`POST /api/v1/products`)
1. แถบ `POST /api/v1/products` → **Try it out**
2. แก้ Request body (ใช้ `category_id` จากแบบฝึกที่ 9 และ SKU ต้องไม่ซ้ำ):
   ```json
   {
     "category_id": 4,
     "supplier_id": 1,
     "name": "Football",
     "price": 590,
     "sku": "SKU-SPT-001",
     "stock_quantity": 10
   }
   ```
3. **Execute** → ✅ Code **201** → **จำ `id` ของสินค้าใหม่ไว้** (เช่น 4)
4. ข้อควรรู้:
   - `sku` **ห้ามซ้ำ** ถ้าซ้ำได้ 500 (ตัวอย่างที่ Swagger เติมให้คือ `SKU-ELE-002` ใช้ได้ครั้งเดียว)
   - `category_id` / `supplier_id` ต้องเป็นเลขที่มีอยู่จริง ไม่งั้นได้ 500
   - `supplier_id` ใส่ `null` ได้ (ไม่ระบุผู้จัดจำหน่าย)

### แบบฝึกที่ 11: แก้ไขราคาสินค้า (`PATCH /api/v1/products/{id}`)
1. แถบ `PATCH /api/v1/products/{id}` → **Try it out**
2. **id** = เลขสินค้าจากแบบฝึกที่ 10
3. ⚠️ **ลบตัวอย่างที่ Swagger เติมให้ออกเกือบหมด** — ตัวอย่างมี `"sku": "SKU-ELE-001"` ซึ่งเป็นของสินค้า ID 1 ถ้าส่งไปแก้สินค้าชิ้นอื่นจะได้ **500 (SKU ซ้ำ)** ให้เหลือแค่ช่องที่อยากแก้:
   ```json
   {
     "price": 650
   }
   ```
4. **Execute** → ✅ Code **200** `"message": "อัปเดตข้อมูลสินค้าสำเร็จ"`
5. เช็ก: `GET /api/v1/products/{id}` ใส่ id เดิม → ราคาเป็น `"650.00"`
6. ลองส่ง body ว่าง `{}` → ✅ Code **400** "ต้องส่งอย่างน้อย 1 ช่อง"
7. ช่องที่แก้ได้: `name`, `sku`, `price`, `stock_quantity`, `category_id`, `supplier_id` (ส่งกี่ช่องก็ได้)

### แบบฝึกที่ 12: ลบสินค้า (`DELETE /api/v1/products/{id}`)
1. แถบ `DELETE /api/v1/products/{id}` (สีแดง) → **Try it out**
2. **id** = เลขสินค้าจากแบบฝึกที่ 10 — ⚠️ **อย่าใส่ 1, 2, 3** ถ้าไม่อยากให้สินค้าตัวอย่างหาย (Swagger **ไม่ถามยืนยัน**ก่อนลบ ต่างจากหน้าเว็บ)
3. **Execute** → ✅ Code **200** `"deleted_id": "4"`
4. เช็ก: `GET /api/v1/products/{id}` id เดิม → ✅ Code **404** (ลบแล้วจริง)
5. ลบหมวดหมู่ Sports ด้วย `DELETE /api/v1/categories/{id}` ได้เช่นกัน (⚠️ ลบหมวดหมู่ = สินค้าในหมวดนั้นถูกลบตามไปด้วย)

### แบบฝึกที่ 13: Logout แล้วลองลบอีกครั้ง
1. กดปุ่ม **Authorize 🔒** ด้านบน → กด **Logout** → **Close**
2. กุญแจทุกแถบกลับเป็นกุญแจเปิด 🔓
3. ลอง `DELETE /api/v1/products/{id}` id = `1` → **Execute**
4. ✅ Code **401** — ลบไม่ได้ สินค้า ID 1 ยังอยู่ (เช็กด้วย GET ได้)

### (ไม่แนะนำตอน demo) เปลี่ยนรหัสผ่าน `PATCH /api/v1/auth/change-password`
- **เปลี่ยนรหัสผ่าน admin จริง** — ถ้าลืมรหัสใหม่ ล้างข้อมูลตาม README หัวข้อ 6 จะกลับเป็นรหัสเริ่มต้น แต่ข้อมูลที่เพิ่มระหว่างซ้อมจะหาย
- body: `{"oldPassword": "รหัสปัจจุบัน", "newPassword": "รหัสใหม่ อย่างน้อย 8 ตัว"}` ต้อง Authorize ก่อน
- ถ้าเปลี่ยนแล้วลืม ดูวิธีตั้งรหัสใหม่ใน [README.md](README.md) ใต้ตาราง "แก้ปัญหาที่เจอบ่อย"

## 6. ส่วน Schemas ท้ายหน้า

เลื่อนลงล่างสุดจะเจอกลุ่ม **Schemas** = **รูปแบบข้อมูล**ที่ API ใช้ กดชื่อเพื่อกางดู เช่น:

| Schema | ใช้ตอนไหน |
|---|---|
| `ProductInput` | body ตอนเพิ่มสินค้า (ช่องที่มี `*` สีแดง = บังคับ) |
| `ProductUpdateInput` | body ตอนแก้ไขสินค้า |
| `Product` | หน้าตาข้อมูลสินค้าที่ตอบกลับ |
| `LoginInput` / `LoginResponse` | body/ผลลัพธ์ตอน login |
| `ErrorResponse` | รูปแบบข้อผิดพลาด `{ error: { code, message } }` |

ในแต่ละ endpoint ก็กดสลับ **Example Value** ↔ **Schema** ดูได้เหมือนกัน (Example Value = ตัวอย่างข้อมูล, Schema = ชนิดข้อมูลแต่ละช่อง)

## 7. ปัญหาที่เจอบ่อย

| อาการ | สาเหตุ | วิธีแก้ |
|---|---|---|
| ไม่มีปุ่ม Execute | ยังไม่ได้กด **Try it out** | กด Try it out ก่อน |
| กด Execute แล้วขึ้น **Failed to fetch** / **TypeError** | เซิร์ฟเวอร์ปิดอยู่ | `npm start` ใหม่ ([หัวข้อ 1](#1-ก่อนเริ่ม-เปิดระบบให้พร้อม)) |
| Code **500** + "อาจเกิดจากข้อมูลซ้ำ" | SKU/ชื่อหมวดหมู่/อีเมล/รหัสผู้จัดจำหน่าย ซ้ำของที่มีอยู่ | เปลี่ยนค่าให้ไม่ซ้ำ |
| Code **500** ตอน PATCH สินค้า | ใช้ตัวอย่างที่ Swagger เติมให้ (มี SKU ของสินค้า ID 1) | ลบช่องที่ไม่ได้แก้ออก ([แบบฝึกที่ 11](#แบบฝึกที่-11-แก้ไขราคาสินค้า-patch-apiv1productsid)) |
| Code **500** + "เกิดข้อผิดพลาดภายในเซิร์ฟเวอร์" ทุก endpoint | ฐานข้อมูลปิด | เปิด Docker Desktop → `docker start stockpro_mysql_test` |
| Code **401** "กรุณาเข้าสู่ระบบก่อนใช้งาน" | ยังไม่ Authorize | ทำ[แบบฝึกที่ 6-7](#แบบฝึกที่-6-login-เพื่อขอ-token-post-apiv1authlogin) |
| Code **401** "Token ไม่ถูกต้องหรือหมดอายุ" | คัดลอก token ไม่ครบ/ติด `"` มา หรือเกิน 1 ชั่วโมง | Authorize → Logout → login ใหม่ → วาง token ใหม่ให้ครบ |
| Code **401** ตอน login | รหัสผ่านผิด หรือยังเป็นคำว่า `"string"` | แก้ password ใน body |
| Request body ขึ้นกรอบแดง / ส่งแล้วได้ 500 แปลกๆ | JSON ผิดรูปแบบ (ลืม `"` ลืม `,` หรือมี `,` เกินท้าย) | กด **Reset** แล้วแก้ใหม่ทีละช่อง |
| Code **400** ตอน PATCH | ส่ง body ว่าง `{}` | ใส่อย่างน้อย 1 ช่องที่ต้องการแก้ |
| หน้า Swagger ไม่อัปเดตหลังแก้ `openapi.yaml` | Swagger อ่านไฟล์ตอนเปิดเซิร์ฟเวอร์ | `Ctrl+C` แล้ว `npm start` ใหม่ + กด `Ctrl+F5` |

## 10. คำศัพท์ที่ควรรู้

| คำ | ความหมายง่ายๆ |
|---|---|
| **API** | ช่องทางให้โปรแกรมคุยกัน — หน้าเว็บ/Swagger ส่งคำขอ เซิร์ฟเวอร์ตอบกลับ |
| **Endpoint** | ที่อยู่ของคำสั่ง 1 อย่าง = Method + Path เช่น `GET /api/v1/products` |
| **Method** | ชนิดคำสั่ง: GET ดู, POST เพิ่ม, PATCH แก้, DELETE ลบ |
| **Path / URL** | ที่อยู่ เช่น `/api/v1/products/1` |
| **Path parameter** | ค่าที่อยู่ใน path เช่น `{id}` |
| **Query parameter** | ค่าหลัง `?` เช่น `?currency=USD` |
| **Request body** | ข้อมูลที่ส่งไป (JSON) ใช้กับ POST/PATCH |
| **Response** | สิ่งที่เซิร์ฟเวอร์ตอบกลับ = Code + body |
| **Status code** | ตัวเลขบอกผล: 2xx สำเร็จ, 4xx ส่งผิด, 5xx เซิร์ฟเวอร์มีปัญหา |
| **JSON** | รูปแบบข้อมูล `{"ชื่อช่อง": ค่า}` |
| **Token / JWT** | "บัตรผ่าน" ที่ได้หลัง login ใช้ยืนยันว่าเป็น admin มีอายุ 1 ชั่วโมง |
| **Authorize** | ปุ่มใส่ token ใน Swagger ให้แนบไปกับทุกคำขอ |
| **OpenAPI / openapi.yaml** | ไฟล์เอกสาร API มาตรฐาน — Swagger อ่านไฟล์นี้มาสร้างหน้าเว็บ |
| **Schema** | รูปแบบ/ชนิดของข้อมูลแต่ละช่อง |
